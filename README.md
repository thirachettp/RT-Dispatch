# SCDC – ระบบจัดการงานรถ Handling (MVP v24 — รองรับ Deploy บน Vercel)

## 🚀 สิ่งที่เพิ่มล่าสุด (รอบนี้ — รื้อสถาปัตยกรรมให้ Deploy บน Vercel ได้)

รอบนี้เป็นงานใหญ่ที่สุดเท่าที่เคยทำในโปรเจกต์นี้ — เปลี่ยนจุดที่เคยพึ่งพา "ไฟล์บน disk" ทั้งหมด (ซึ่ง Vercel
ไม่มีให้เลย) ให้ย้ายเข้า database แทน **ทดสอบด้วยการติดตั้ง PostgreSQL จริงและรันแอปทั้งตัวใส่จริง ไม่ใช่แค่
อ่านโค้ดแล้วเดา** — ระหว่างทางเจอบั๊กจริง 4 ตัวที่ผ่านการทดสอบ SQLite มาหมดแล้วแต่พังทันทีบน Postgres

### สิ่งที่เปลี่ยน
1. **Database: SQLite → รองรับ Postgres ด้วย** — ตั้งค่า environment variable `DATABASE_URL` แล้วแอปจะสลับ
   ไปใช้ Postgres โดยอัตโนมัติ ไม่ต้องแก้โค้ดอะไรเพิ่ม ถ้าไม่ตั้งค่าไว้จะใช้ SQLite เหมือนเดิมทุกอย่าง (รันบน
   Replit/เครื่องตัวเองได้เหมือนเดิม 100%)
2. **VAPID key (Push notification) ย้ายจากไฟล์ไป database** — นี่คือการแก้ปัญหา BadJwtToken แบบถอนรากถอนโคน
   จริงๆ เพราะไฟล์ `vapid_private.pem` มีสิทธิ์หายได้เสมอเวลา deploy ใหม่ (ยืนยันบน Replit ไปแล้วก่อนหน้านี้)
   แต่ Vercel คือหายแน่นอน 100% ทุกครั้ง — ตอนนี้ไม่มีไฟล์นี้อีกแล้ว
3. **รูปถ่ายที่แนบกับงาน ย้ายจากไฟล์ไป database** — เหตุผลเดียวกัน มี**บั๊กแถมที่เจอระหว่างทาง**: พอเปลี่ยนเป็น
   endpoint ที่ต้อง login ถึงจะดูรูปได้ (ปลอดภัยกว่าของเดิมที่ใครก็เปิดดูได้) ปรากฏว่า `<img src="...">` ธรรมดา
   แนบ token ไม่ได้ ทำให้รูปหายไปเงียบๆ — แก้แล้วด้วยการให้หน้าเว็บดึงรูปผ่าน JavaScript พร้อมแนบ token ก่อน
   ค่อยเอามาแสดง (ทดสอบแล้วว่ารูปที่ได้ตรงกับต้นฉบับทุกไบต์)
4. **ไฟล์ตั้งค่าสำหรับ Vercel** — เพิ่ม `pyproject.toml` (บอก Vercel ว่า FastAPI app อยู่ตรงไหน เพราะ
   `backend/main.py` ไม่ได้อยู่ในตำแหน่งที่ Vercel มองหาอัตโนมัติ) และ `vercel.json`

### 🐛 บั๊กที่เจอจากการทดสอบ Postgres จริง (ไม่ใช่แค่อ่านโค้ด)
1. **การแปลง `?` เป็น `%s` ของตัวเองมีบั๊ก** — แปลงแบบ blind replace ไปโดนอักขระ `?` ที่เป็นข้อมูลจริง (ไม่ใช่
   placeholder) เช่น pattern regex ของโซนที่มี `?` เป็นส่วนหนึ่งของ regex (`([A-G][12])?`) ทำให้ข้อมูลเพี้ยน
   แก้โดยเขียนตัวแปลงที่ฉลาดขึ้น รู้จักแยกว่าอยู่ในเครื่องหมายคำพูดหรือไม่ก่อนแปลง
2. **`INSERT OR IGNORE`** เป็นไวยากรณ์เฉพาะของ SQLite ที่ Postgres ไม่รู้จักเลย ใช้อยู่ 2 จุด (สิทธิ์ขับรถ,
   เมทริกซ์รถ-โซน) แก้เป็น `ON CONFLICT DO NOTHING` ซึ่งใช้ได้ทั้งสองฐานข้อมูล
3. **Column reference ambiguous** ในการนับเลขที่งาน (`next_seq = next_seq + 1`) — Postgres งงว่าหมายถึงตัว
   ไหน ทั้งที่ SQLite ไม่มีปัญหานี้เลย แก้โดยระบุชื่อตารางให้ชัดเจน

**ทดสอบครบทุก flow หลักกับ Postgres จริงหลังแก้เสร็จ**: login/สมัคร (ทั้งรหัสพนักงานและอีเมล), สร้าง
คนขับ+รถ, วงจรงานเต็ม (มอบหมาย→เริ่ม→เสร็จ→ให้คะแนน), หยุด/ทำต่อ, งานหลายคนขับ (เพิ่ม/ออกจากงาน), ตีกลับ/
ส่งใหม่, ยกเลิก, ทำเครื่องหมายเสร็จโดย Admin, แชทงาน+แชททีม, รายงานปัญหา+แก้ไข, ประกาศ+แจ้งเตือน, ใบอนุญาต
ขับรถ, ลบผู้ใช้, Export Excel, Dashboard, อัปโหลด/ดูรูปถ่าย — **และทดสอบ race condition ซ้ำอีกครั้งบน Postgres
โดยเฉพาะ** (คนขับ 6 คนแย่งงานเดียวกันพร้อมกันจริง) ได้ผลถูกต้องเหมือนที่เคยทดสอบบน SQLite ทุกประการ

## 📋 วิธี Deploy บน Vercel

1. สร้าง Postgres database บน Vercel (Storage → Create Database → Postgres) จะได้ `DATABASE_URL` มาอัตโนมัติ
2. เอาโค้ดขึ้น GitHub แล้ว import เข้า Vercel (หรือใช้ `vercel` CLI จาก root โปรเจกต์นี้โดยตรง)
3. Vercel จะรู้จัก FastAPI app จาก `pyproject.toml` ที่เพิ่มไว้ให้อัตโนมัติ ไม่ต้องตั้งค่า build command เอง
4. Deploy แล้วรอ — ครั้งแรกที่มีคน request เข้ามา แอปจะสร้างตารางทั้งหมด + บัญชี Admin เริ่มต้นให้อัตโนมัติ
   เหมือนตอนรันครั้งแรกบนเครื่องปกติ (**เช็ค Vercel deployment logs หารหัสผ่าน Admin ที่พิมพ์ออกมาครั้งเดียว**)

## ⚠️ สิ่งที่ยังไม่ได้ทดสอบ (ทดสอบกับ Postgres ที่ติดตั้งเองในเครื่องทดสอบ ไม่ใช่ Vercel ของจริง)
- Vercel Postgres ตัวจริงอาจมีข้อจำกัดเรื่อง connection pooling ที่ Postgres ธรรมดาไม่มี (เช่น ต้องใช้ connection
  string แบบ pooled สำหรับ serverless functions) — ควรลองใช้งานจริงหลัง deploy แล้วสังเกตอาการ connection
  timeout ถ้าเจอ
- Cold start / timeout จริงบน Vercel (เคยคุยเชิงทฤษฎีไปแล้วก่อนหน้านี้ ยังไม่ได้วัดจริง)

# SCDC – ระบบจัดการงานรถ Handling (MVP v23 — ทดสอบ Push จริง + Default เปิดไว้)

## 🔔 สิ่งที่เพิ่มล่าสุด (รอบนี้)

### 1. ทดสอบการแจ้งเตือนจริงตอนเปิดใช้งาน
กด "เปิดการแจ้งเตือน" ตอนนี้จะ**ส่ง push ทดสอบจริงทันที** แล้วบอกผลตรงๆ ในหน้าเลย:
- ✅ "ทดสอบสำเร็จ" — ถ้าส่งได้จริง
- ⚠️ "เปิดใช้งานแล้ว แต่ทดสอบส่งไม่สำเร็จ: [เหตุผล]" — ถ้ามีปัญหา เช่น ยังไม่ได้ตั้งค่า HTTPS/VAPID key,
  หรือ subscription มีปัญหา (เช่น BadJwtToken ที่เจอไปก่อนหน้า) — **ครั้งนี้จะเห็นทันทีตอนเปิดใช้งาน ไม่ต้อง
  รอไปเจอตอนมีแจ้งเตือนจริงแล้วไม่ขึ้นแบบเงียบๆ เหมือนก่อน**

ทดสอบแล้วครบ: ไม่มี subscription เลย → บอกเหตุผลชัดเจน, subscription เสีย → error แบบ graceful ไม่ล่ม
เซิร์ฟเวอร์

### 2. Notification + Zoom Default เปิดไว้ให้อัตโนมัติ
- **Zoom**: default เปิดอยู่แล้วตั้งแต่รอบที่แล้ว (เช็คโค้ดยืนยันแล้วว่าเป็นค่าเริ่มต้นถูกต้อง) ปิดแล้วจำทันที
  ไม่หายตอนล็อกอินใหม่ (จำเฉพาะเครื่อง)
- **Notification**: เพิ่มการ "เสนอเปิดให้อัตโนมัติครั้งเดียว" ตอนล็อกอินเข้าแอปครั้งแรกที่รองรับ (คนละกรณีกับ
  Zoom เพราะ Push ต้องขอสิทธิ์จากเบราว์เซอร์เสมอ **ไม่มีทางเปิดให้เองแบบเงียบๆ ได้** — เป็นข้อจำกัดของเบราว์เซอร์
  เอง ไม่ใช่ของแอป) ระบบจะเด้ง popup ขออนุญาตของเบราว์เซอร์ให้อัตโนมัติแค่ครั้งเดียวต่อเครื่อง ไม่ว่าผลจะเป็น
  อนุญาตหรือปฏิเสธก็จะไม่เด้งซ้ำอีก — และถ้า user กดปิดเองทีหลังในหน้าโปรไฟล์ ก็จะไม่เด้งถามซ้ำเช่นกัน

# SCDC – ระบบจัดการงานรถ Handling (MVP v22 — Dashboard/Operation ปรับใหม่ + แก้บั๊ก)

## 📊 สิ่งที่เพิ่มล่าสุด (รอบนี้)

### 1. เพิ่มหน้าโปรไฟล์ให้ Admin
Admin มีแท็บ "โปรไฟล์" แล้ว (ใช้หน้าเดียวกับ User/Driver) แก้ชื่อ/อีเมล/เบอร์/รหัสผ่าน, เปิด-ปิดแจ้งเตือน,
เปิด-ปิดการซูมได้เหมือนกันหมด

### 2. Dashboard ปรับให้ดูง่ายขึ้น + แก้กระพริบ
- **จัดกลุ่ม KPI ใหม่** จากเดิมเรียงตัวเลข 9 ตัวปนกันหมดเป็นตารางเดียว (นี่คือสาเหตุหลักที่ "ดูยาก") แยกเป็น
  2 กลุ่มชัดเจน: **"สถานะงาน"** (งานทั้งหมด/กำลังทำ/ค้างนาน/เสร็จสิ้น/อัตราสำเร็จ) กับ **"ประสิทธิภาพ"**
  (เวลาเฉลี่ย/พาเลทต่อชม./การใช้งานคน/การใช้งานรถ)
- **แก้บั๊กกระพริบ** — ต้นเหตุคือ Dashboard เคยถูก rebuild ใหม่ทั้งหน้าทุก 3 วินาทีตาม auto-refresh ของทั้งแอป
  ทำให้เห็น "กำลังโหลด..." กระพริบซ้ำๆ ทั้งที่ตัวเลขจริงไม่ได้เปลี่ยนบ่อยขนาดนั้น ตอนนี้ตัด Dashboard ออกจาก
  auto-refresh 3 วิแล้ว จะโหลดใหม่แค่ตอน: เปิดแท็บ, เปลี่ยนช่วงเวลา, หรือกดรีเฟรชเอง
- **เพิ่มปุ่มรีเฟรชด้วยมือ + เลื่อนลงเพื่อรีเฟรช (pull-to-refresh)** ใช้งานบนมือถือได้จริง (ดึงหน้าจอลงตอน
  อยู่บนสุดของหน้า จะขึ้น "ดึงลงเพื่อรีเฟรช" แล้วเปลี่ยนเป็น "ปล่อยเพื่อรีเฟรช" เมื่อดึงพอ)
- **โชว์เวลาที่อัปเดตล่าสุด** ("อัปเดตล่าสุด HH:MM:SS") ให้รู้ว่าเลขที่เห็นสดแค่ไหน

### 3. หน้าปฏิบัติการ — เพิ่มสรุปข้อมูลสำคัญ + filter ให้ครบทุกเมนู
- **งาน** — เพิ่มแถบสรุป: รอดำเนินการ / กำลังดำเนินการ / ค้างนาน (Overdue) ก่อน filter เดิม
- **พนักงาน** — เพิ่มแถบสรุป **"คนขับออนไลน์ตอนนี้ X/Y"** + จำนวน User/Admin พร้อม**เพิ่ม filter ตาม Role**
  (เดิมมีแค่ช่องค้นหาข้อความอย่างเดียว)
- **รถ** — เพิ่มแถบสรุป รถว่าง/ไม่ว่าง/ขัดข้อง + **เพิ่ม filter ตามสถานะรถ**
- **ปัญหา** — เพิ่มแถบสรุป ยังไม่แก้ไข/แก้ไขแล้ว + **เพิ่ม filter Open/Resolved** (เดิมไม่มี filter เลย)

### 🐛 4. แก้บั๊ก "Admin เลื่อนดูคนขับเพื่อมอบหมายงานไม่ได้"
พบว่ารายชื่อคนขับในหน้ามอบหมายงานไม่มีขอบเขตความสูง ยาวไม่จำกัดตามจำนวนคนขับ ถ้ามีคนขับเยอะจะดันปุ่ม
"ยืนยันมอบหมาย" ตกไปไกลจนหาไม่เจอ/รู้สึกเหมือนเลื่อนไม่ได้ แก้โดย**จำกัดความสูงรายชื่อคนขับให้ scroll ในตัวเอง
ได้ชัดเจน** พร้อม**เพิ่มช่องค้นหาคนขับ**ด้วยเพื่อหาได้เร็วขึ้นเวลามีคนขับเยอะ

# SCDC – ระบบจัดการงานรถ Handling (MVP v21 — เปลี่ยนรูปแบบเลขที่งาน)

## 🔢 สิ่งที่เพิ่มล่าสุด (รอบนี้)

### เปลี่ยนเลขที่งานเป็น `TK{YYMMDD}-{ลำดับ}`
จากเดิมที่เป็นตัวเลข timestamp อ่านไม่รู้เรื่อง (เช่น `TK12611205`) เปลี่ยนเป็นรูปแบบที่มีความหมาย:
**`TK260910-001`** = งานที่ 1 ของวันที่ 10 กันยายน 2026 — ลำดับรีเซ็ตเป็น 001 ใหม่ทุกวัน (นับตามเวลาไทย
ไม่ใช่ UTC เพื่อไม่ให้เลขที่งานเปลี่ยนวันตอนตี 7 เช้าซึ่งจะงงเปล่าๆ)

**ออกแบบให้ปลอดภัยจาก race condition โดยเฉพาะ** — เพราะรอบก่อนๆ เจอบั๊กจากการที่หลายคนกดพร้อมกันมาแล้ว
รอบนี้เลยใช้ตาราง counter แยกต่างหาก อัปเดตแบบ atomic ในคำสั่ง SQL เดียว (`UPSERT + RETURNING`) รับประกันว่า
ต่อให้มีคนสร้างงานพร้อมกันกี่คนก็ตาม จะไม่มีทางได้เลขที่ซ้ำกันเด็ดขาด

**ทดสอบยิง request สร้างงานพร้อมกันจริง 15 คำขอในเวลาเดียวกันเป๊ะ** (ไม่ใช่แค่ทดสอบเรียงลำดับ) — ผลลัพธ์:
สำเร็จครบทั้ง 15 คำขอ ได้เลขที่ไม่ซ้ำกันเลยสักตัว

หมายเหตุ: ถ้าวันไหนมีงานเกิน 999 งาน เลขจะยาวเกิน 3 หลักไปเอง (เช่น `TK260910-1000`) ไม่ error และไม่วนกลับ
ไปเริ่มที่ 001 ใหม่

# SCDC – ระบบจัดการงานรถ Handling (MVP v20 — แก้อีเมลที่ตกหล่นจาก v19)

## 🔧 สิ่งที่แก้ล่าสุด (รอบนี้ — คุณถามว่า "ลืมเรื่องอีเมลหรือเปล่า" แล้วใช่จริงๆ)

รอบ v19 ทำแค่ **login/register** ให้ใช้อีเมลได้ แต่ลืมเชื่อมจุดอื่นที่เกี่ยวข้องไปหมด — จุดที่สำคัญที่สุดคือ
**คนขับ (Driver) ซึ่ง Admin เป็นคนสร้างบัญชีให้ ไม่เคยมีช่องให้ใส่อีเมลเลย แปลว่าคนขับทุกคน "ใช้อีเมล login
ไม่ได้จริง" ทั้งที่ USER ทำได้** อันนี้เป็นช่องโหว่ใหญ่ของฟีเจอร์นี้ แก้ครบแล้วทุกจุด:

1. **`/me` (ดูโปรไฟล์ตัวเอง)** — ไม่เคยส่งค่าอีเมลกลับมาเลย ทำให้หน้าโปรไฟล์โชว์อีเมลไม่ได้ตั้งแต่ต้น
2. **หน้าโปรไฟล์ (แก้ไขข้อมูลส่วนตัว)** — เพิ่มช่องอีเมล ให้ทุก role (User/Driver/Admin) เพิ่ม/แก้อีเมลของ
   ตัวเองได้ทีหลัง ไม่ต้องรอใส่ตอนสมัครสมาชิกอย่างเดียว
3. **Admin สร้างบัญชีคนขับใหม่** — เพิ่มช่องอีเมล ให้ Admin ใส่ตอนสร้างบัญชีให้คนขับได้เลย (นี่คือจุดที่ขาดไป
   สำคัญที่สุด)
4. **Admin แก้ไขข้อมูลพนักงาน (People → แก้ไข)** — เพิ่มช่องอีเมล ให้ Admin เพิ่ม/แก้อีเมลให้ใครก็ได้ทีหลัง
5. **รายชื่อพนักงานที่ Admin เห็น** — โชว์อีเมลในรายการ + ค้นหาด้วยอีเมลได้ด้วย

**เพิ่มฟังก์ชันกลาง `validate_and_normalize_email()`** ให้ทั้ง 4 จุด (register, แก้โปรไฟล์ตัวเอง, สร้างคนขับ,
Admin แก้ไขคนอื่น) เรียกใช้ร่วมกัน — เช็คโดเมน @central.co.th และเช็คอีเมลซ้ำแบบเดียวกันทุกที่ ไม่ต้องเขียนซ้ำ
4 รอบและเสี่ยงพลาดจุดใดจุดหนึ่งแบบที่เพิ่งเกิดขึ้น

**ทดสอบครบ 7 สถานการณ์**: สร้างคนขับพร้อมอีเมล → คนขับ login ด้วยอีเมลได้จริง (เทสต์ตรงจุดที่เคยพัง) →
`/me` ส่งอีเมลกลับมาถูกต้อง → คนขับแก้อีเมลตัวเองได้ → รายชื่อ Admin เห็นอีเมลครบ → Admin แก้อีเมลคนอื่นได้ →
โดเมนผิดโดนบล็อกทุกจุดเหมือนกันหมด

   ที่ Admin มีอยู่แล้วจากรอบก่อน)
4. **ป้องกันการ Login ซ้ำ** — ล็อกอินเครื่อง/เบราว์เซอร์ใหม่จะตัด session เก่าทิ้งอัตโนมัติ ทดสอบแล้วว่า

### Register
2. รหัสพนักงานซ้ำ หรือ อีเมลซ้ำ → แจ้งเป็นภาษาไทยชัดเจนแยกกรณี
3. **แยกช่องชื่อ-นามสกุล วางคู่กันซ้าย-ขวา**
4. **เบอร์ติดต่อ auto-format เป็น xxx-xxx-xxxx ขณะพิมพ์** พร้อมเตือนทันทีถ้าไม่ตรงรูปแบบ (ใช้จุดเดียวกับ
   หน้าแก้ไขโปรไฟล์ด้วย เพื่อความสม่ำเสมอ)

### 🐛 Profile — เจอบั๊กจริง 2 จุด แก้ให้แล้ว
1. **"แก้ไขแล้วไม่เกิดการแก้ไขจริง"** → พบว่า header (ชื่อที่โชว์มุมซ้ายบน) ไม่เคยอัปเดตหลังแก้โปรไฟล์เลย
   เพราะ header ถูกสร้างแค่ครั้งเดียวตอน login ข้อมูลจริงบันทึกถูกต้องเสมอ แค่หน้าจอไม่ยอมอัปเดตให้เห็น —
   แก้แล้วให้ header รีเฟรชทันทีหลังกดบันทึก ไม่ต้องรอ reload หน้า
2. **"ลบแล้วไม่หายไป"** → พบว่ามีหลายจุดที่ query ลืมกรองบัญชีที่ถูกลบออก (`deleted_at`) ทำให้ User/Driver ที่
   ลบไปแล้วยังโผล่ใน: รายชื่อแชททีม, การ @mention, คำแนะนำมอบหมายงาน, และที่สำคัญที่สุดคือ **ตัวเลขสถิติ
   คนขับในหน้า Dashboard ของ Admin** (นับคนขับที่ถูกลบไปแล้วรวมด้วยตลอดไป) แก้ครบทุกจุดแล้ว ทดสอบยืนยันว่า
   ลบแล้วหายจากรายชื่อแชททีมจริง

### 🔔 Notification — ทำไม Push ไม่เด้งนอกแอป
ตรวจโค้ดแล้วไม่พบบั๊ก แต่**หาสาเหตุที่เป็นไปได้ไม่ได้เพราะไม่มี log ให้เช็คเลย** — เพิ่ม log ที่ server เข้าไป
ในทุกจุดตัดสินใจของการส่ง push แล้ว ครั้งหน้าที่แจ้งเตือนไม่เด้ง **ให้เปิดดู log ของ server** จะบอกได้ทันทีว่า
สาเหตุคืออะไรในนี้:
- ยังไม่ได้เปิดสวิตช์แจ้งเตือนในหน้าโปรไฟล์เลย (ไม่มี subscription บันทึกไว้) — **สาเหตุที่เป็นไปได้มากที่สุด**
- ยังไม่ได้ตั้งค่า HTTPS (`setup-https.bat`) — Push **ต้องมี HTTPS เท่านั้น** ถ้าเข้าผ่าน HTTP ธรรมดาจะเปิด
  สวิตช์ไม่ได้ตั้งแต่แรก (มีข้อความเตือนอยู่แล้วในหน้าโปรไฟล์)
- **มือถือ iPhone ต้อง "เพิ่มลงหน้าจอโฮม" ก่อน** ถึงจะรับ Push ได้ — เปิดผ่าน Safari ธรรมดาจะไม่มีทางได้รับ
  Push เลย เป็นข้อจำกัดของ iOS เอง ไม่ใช่บั๊กของแอป
- เซิร์ฟเวอร์เข้าอินเทอร์เน็ตออกไปหา Push relay ของ Google/Apple/Mozilla ไม่ได้ (เช่น อยู่หลัง firewall บริษัท
  ที่บล็อก outbound traffic) — ถ้าเป็นกรณีนี้ log จะโชว์ error ตอนพยายามส่งชัดเจน

แปลง CSS variable ทั้งชุดจากพื้นเข้ม+ตัวหนังสือสว่าง เป็นพื้นขาว+ตัวหนังสือเข้ม พร้อมไล่แก้สีที่ hardcode ไว้

สีส้ม amber เปลี่ยนเป็นสีน้ำเงิน และ**เพิ่มตัวแปรสีใหม่ `--warn`** แยกออกมาสำหรับสถานะเตือน/ระวังโดยเฉพาะ

  ไม่ต้องรีเฟรชหน้า)
- **ขวาบนของ Driver**: เรียงเป็น สถานะ (กดเปลี่ยนได้เลย) → แชท → แจ้งเตือน ตามที่ขอ

- ปุ่ม "อ่านทั้งหมด" ที่มุมขวาบนของหน้าแจ้งเตือน (โชว์เฉพาะตอนมีรายการยังไม่อ่าน)

JS/CSS syntax สะอาด, brace balance ตรง, สร้างเซิร์ฟเวอร์ใหม่ทั้งหมดแล้วยืนยันว่า: header โชว์ชื่อ+role+รหัส

# SCDC – ระบบจัดการงานรถ Handling (MVP v17 — Validation รอบใหญ่ + จัดการ User/ปัญหาได้ดีขึ้น)

## ✅ สิ่งที่เพิ่มล่าสุด (รอบนี้ — Validation + Admin tools)

### Validation ที่แก้ตามที่ตัดสินใจ
1. **รหัสผ่านต้องมีอย่างน้อย 6 ตัวอักษร** — เช็คทั้ง backend (`register`/`set-password`/`change-password`)

2. ข้าม (ตามที่แจ้งว่าไม่ต้อง)
3. **`pallet_qty` ต้องเป็นเลขบวกเท่านั้น** — ส่ง 0 หรือติดลบจะโดนปฏิเสธทันทีตั้งแต่ระดับ validation ก่อนถึง
   business logic เลย
4. **เอา `capacity_pallet` ออกทั้งระบบ** — ตามแนวทางเดียวกับที่เอา "ชั้นวางสูงสุด" ออกไปก่อนหน้านี้ ไม่มีการ
   กำหนดความจุพาเลทตายตัวต่อรถอีกต่อไป ลบออกจาก schema, ฟอร์มสร้าง/แก้ไขรถ, การเช็คสิทธิ์ตอนมอบหมายงาน
5. **ยังไม่ได้ทำ** — ขอชี้แจงคำถามเดิมใหม่ให้ชัดขึ้น: ตอนนี้ช่อง "ความสำคัญ" (priority) และ "ประเภทคำขอ"
   (request_type) ยังไม่ได้บังคับว่าต้องเป็นค่าที่ระบบรู้จักเท่านั้น (เช่น "Normal"/"High"/"Low") ถ้ามีคนยิง
   API ตรงๆ ใส่ค่าอื่นเข้ามา (เช่น "Urgent") ระบบจะรับไว้เฉยๆ แล้วหน้าเว็บอาจแสดงผลเพี้ยนเพราะไม่รู้จักค่านั้น
   — อยากให้ล็อกให้เลือกได้แค่ค่าที่กำหนดไว้ไหม บอกได้เลยรอบหน้า
6. **ปรับแล้ว** — วันหมดอายุใบอนุญาตต้องเป็นรูปแบบ `YYYY-MM-DD` จริงเท่านั้น ใส่ข้อความมั่วๆ จะโดนปฏิเสธ
7. **บังคับห้ามว่าง** — ส่งประกาศด้วยข้อความว่างไม่ได้แล้ว
8. **Admin ลบ User ได้ + รีเซ็ตรหัสผ่านให้คนอื่นได้ ("ลืมรหัสผ่าน")**
   - ลบ User ใช้วิธี **soft delete** (ไม่ได้ลบแถวจริงออกจากฐานข้อมูล) เพราะประวัติงาน/แชท/audit log ของคนนั้น
     ยังอ้างอิงถึง user id นี้อยู่ ถ้าลบจริงจะทำให้ข้อมูลเก่าพังหรือลบไม่ได้เลย — บัญชีที่ถูกลบจะ**ล็อกอินไม่ได้
     อีก** และ session ที่ค้างอยู่จะถูกตัดทันที แต่ประวัติเก่ายังดูได้ปกติ ป้องกันการลบตัวเองและลบ Admin
     คนสุดท้ายไว้ด้วย
   - "รีเซ็ตรหัสผ่าน" ให้คนอื่น ใช้กลไกเดียวกับตอนสร้างบัญชีใหม่ (บังคับตั้งรหัสผ่านใหม่ตอนล็อกอินครั้งถัดไป)
     ไม่ต้องสร้างระบบใหม่ ปุ่มทั้งสองอยู่ในหน้าแก้ไขพนักงาน (Operation → พนักงาน → แก้ไข)
9. **แจ้งเตือนเมื่อแก้ไขปัญหาแล้ว** — Admin กด "ทำเครื่องหมายว่าแก้ไขแล้ว" ตอนนี้เปิดให้ใส่บันทึกวิธีแก้ไขได้
   (ไม่บังคับ) แล้วส่งแจ้งเตือนถึงคนที่รายงานปัญหานั้นพร้อมข้อความที่ใส่ไว้ (ฝั่ง User แก้ไขงานที่ถูกตีกลับแล้ว
   กดส่งใหม่ ก็แจ้งเตือน Admin อยู่แล้วตั้งแต่ก่อนหน้านี้)

### UX/UI
- ข้อ 1-2 (empty state, driver ติดหน้าเช็คอิน) — คงไว้แบบเดิมตามที่แจ้งว่าไม่เป็นไร

uvicorn เอง) และจะไปอ่านค่า **environment variable `PORT`** อัตโนมัติ (Replit/Render/Railway/Heroku ทุกตัว
กำหนด port ผ่านตัวแปรนี้เหมือนกัน) ถ้าไม่มีค่า PORT จะ fallback เป็น 8000 เหมือนเดิม — วิธีรันแบบเดิมผ่าน
`uvicorn main:app --reload` หรือ `start-server.bat` ก็ยังใช้ได้ปกติ ไม่กระทบกัน

## ⚠️ สิ่งที่ควรตรวจสอบเพิ่มก่อน Deploy จริงบน Replit (ยังไม่ได้แก้โค้ด แต่ควรรู้ไว้)

1. **Storage แบบ Persistent หรือไม่** — ถ้าใช้ Replit **"Autoscale Deployments"** ตัว filesystem มักจะไม่
   คงอยู่ถาวรข้าม instance/redeploy หมายความว่า **ไฟล์ `scdc.db` อาจหายได้ทุกครั้งที่ deploy ใหม่หรือ scale**
   ถ้าต้องการเก็บข้อมูลจริงถาวร แนะนำใช้ **"Reserved VM"** แทน หรือรันอยู่ใน Workspace ตรงๆ (ทั้งสองแบบนี้
   ไฟล์จะอยู่ถาวร) — ควรเช็คให้ชัดก่อนใช้งานจริงเพราะกระทบข้อมูลทั้งระบบโดยตรง
2. **`vapid_private.pem`** (คีย์ลับสำหรับ Web Push) — ไฟล์นี้จะถูกสร้างอัตโนมัติตอนรันครั้งแรก **ห้าม commit
   เข้า Git repo ที่เป็น public** เด็ดขาด ถ้า Repl ของคุณ public อยู่ ให้เพิ่มไฟล์นี้ลง `.gitignore`
3. **HTTPS ได้ฟรีจาก Replit** — โดเมนของ Replit (`*.replit.app`) เสิร์ฟผ่าน HTTPS ให้อัตโนมัติอยู่แล้ว แปลว่า
   ฟีเจอร์ Web Push ที่เตรียมไว้ก่อนหน้า (ที่ต้องรอ mkcert/HTTPS เอง) **อาจใช้งานได้ทันทีบน Replit โดยไม่ต้อง
   ตั้งค่า HTTPS เพิ่มเอง** — ยังไม่ได้ทดสอบจริงบน Replit แต่ในทางทฤษฎีควรได้เลย
4. **หน้า `/docs` และ `/redoc`** (Swagger UI ของ FastAPI) เปิดสาธารณะอยู่ (ไม่ต้อง login) โชว์ทุก endpoint
   ที่มีในระบบ — ถ้าไม่อยากให้คนนอกเห็นโครงสร้าง API ทั้งหมด บอกได้ ปิดได้ง่ายๆ (เพิ่ม `docs_url=None,
   redoc_url=None` ตอนสร้าง FastAPI app)
5. **ยังไม่มีการจำกัดจำนวนครั้ง login ผิด** (rate limiting) — ถ้าอยากให้ป้องกัน brute-force รหัสผ่านเพิ่มเติม
   บอกได้ ทำเพิ่มให้ได้ภายหลัง ไม่ใช่เรื่องด่วนสำหรับใช้งานภายในทีมเล็กๆ

# SCDC – ระบบจัดการงานรถ Handling (MVP v15 — แก้ Race Condition + UI งานใหม่)

## สิ่งที่เพิ่มล่าสุด (รอบนี้)

> **หมายเหตุ**: รอบนี้ส่งไฟล์แบบเต็มไฟล์ (ไม่ใช่แค่ diff) ตามที่ขอ — เอา `backend/main.py` และ
> `frontend/index.html` ไปแทนที่ไฟล์เดิมได้เลยทั้งไฟล์ **ไม่ต้องลบ `scdc.db`** เพราะระบบ auto-migration
> จากรอบก่อนจะจัดการให้เอง (แต่รอบนี้ไม่มีการเปลี่ยน schema เพิ่มเติมนอกจากเพิ่ม index ซึ่งไม่กระทบข้อมูลเดิม)

### 🐛 แก้บั๊ก Race Condition ตอนกดพร้อมกัน (Concurrency)
ไล่เจอสาเหตุจริง: ฟังก์ชัน `transition()` (เปลี่ยนสถานะงาน) เดิมเขียนแบบ `UPDATE tasks SET status=? WHERE
id=?` **ไม่มีเงื่อนไขเช็คสถานะปัจจุบันตอนเขียนจริง** ทำให้ถ้ามี 2 คำขอมาถึงพร้อมกันเป๊ะๆ (เช่น คนขับ 2 คน
กด "รับงานนี้" งานเดียวกันพร้อมกัน) ทั้งคู่อาจอ่านเห็นสถานะเดิมพร้อมกันแล้วเขียนทับกันได้ ทำให้เกิดงานที่มี
คนขับซ้อนกันผิดปกติ

**วิธีแก้** (ทดสอบด้วยการยิง request จริงพร้อมกันจริงๆ ผ่าน multi-threading ไม่ใช่แค่ทดสอบเรียงลำดับ):
1. เพิ่ม **unique index ระดับฐานข้อมูล** บน `task_assignments(task_id, driver_id)` เฉพาะแถวที่
   `assignment_status='Active'` — ทำให้ฐานข้อมูลเองปฏิเสธการสร้างแถว "กำลังทำงาน" ซ้ำสำหรับคนขับคนเดียวกัน
   ในงานเดียวกันโดยอัตโนมัติ ไม่ว่า timing จะบังเอิญชนกันแค่ไหนก็ตาม
2. เปลี่ยนการเปลี่ยนสถานะ "รอดำเนินการ" → "มอบหมายแล้ว" ให้เป็น atomic (เช็คเงื่อนไขตอนเขียนจริงในคำสั่ง
   เดียว ไม่ใช่เช็คแยกจากการเขียน) ถ้ามีคนอื่นชิงไปก่อนจะได้ error ที่ชัดเจนทันที ("งานนี้ถูกมอบหมายไปแล้ว
   โดยคนอื่น") แทนที่จะเกิดข้อมูลขัดแย้งกันเงียบๆ
3. ครอบคลุมทุกจุดที่เพิ่มคนขับเข้างาน: รับงานเอง (self-assign), เข้าร่วม (join), Admin เพิ่มคนขับ,
   Admin มอบหมาย/มอบหมายใหม่

**ผลทดสอบจริง** (ยิง request พร้อมกันจริงด้วย multi-threading + barrier บังคับให้ยิงพร้อมกันเป๊ะ):
- คนขับ 2 คนต่างกันรับงานเดียวกันพร้อมกัน → ชนะแค่ 1 คน อีกคน error สะอาด ไม่มีข้อมูลค้าง ✅
- คนขับคนเดียวกันกดปุ่ม "เข้าร่วม" งานเดียวกันซ้ำๆ พร้อมกัน (กดซ้ำเร็วๆ) → เข้าร่วมสำเร็จแค่ 1 ครั้ง ไม่ซ้ำ ✅
- คนขับ 6 คนรับงานเดียวกันพร้อมกันทีเดียว (stress test) → ชนะแค่ 1 คนเท่านั้น จากทั้งหมด 6 คำขอ ✅

**บั๊กแถมที่เจอระหว่างทาง**: "ทำเครื่องหมายเสร็จ" (admin-complete) เคย crash ถ้าใช้กับงานที่ยังเป็นสถานะ
"มอบหมายแล้ว" (ยังไม่เริ่ม) เพราะ state machine ไม่รองรับ Assigned→Completed โดยตรง แก้แล้วโดยจำกัดปุ่มนี้
ให้ใช้ได้เฉพาะงานที่ "กำลังทำ"/"หยุดชั่วคราว" เท่านั้น (งานที่ยังไม่เริ่มให้ใช้ "ยกเลิก" หรือ "มอบหมายใหม่"
แทน) ทั้ง backend และปุ่มในหน้าเว็บ

### User — ปรับฟอร์มสร้าง/แก้ไขงานใหม่
1. **จำนวนพาเลทเป็น Slider แล้ว** (1-30 พาเลท) แทนการพิมพ์ตัวเลข
2. **จุดต้นทาง/ปลายทาง วางคู่กันซ้าย-ขวา** แทนที่จะเรียงต่อกันแนวตั้งเหมือนเดิม
3. **เปลี่ยนเป็นปุ่มกดเพื่อเปิด popup เลือก** — จากเดิมที่ตัวเลือกโซน+ตำแหน่งฝังอยู่ในฟอร์มยาวๆ ตอนนี้
   แต่ละจุด (ต้นทาง/ปลายทาง) เป็นปุ่มเดียวที่โชว์ค่าที่เลือกไว้ กดแล้วเปิด popup แยกมาให้เลือกโซน+ตำแหน่ง
   เต็มรูปแบบเหมือนเดิมทุกอย่าง (รองรับ paste จาก Excel, ป้องกันซ้ำ ฯลฯ) แค่ย้ายมาอยู่ใน popup แทน
   ทำให้ฟอร์มหลักกระชับพอจะวางสองจุดคู่กันซ้าย-ขวาได้

### General — ตรวจสอบซ้ำเรื่อง "ชั้นวางสูงสุด"
ยืนยันแล้วว่าไม่มีร่องรอยเหลืออยู่เลยทั้ง backend และ frontend (เหลือแค่ในโค้ด migration ที่จงใจอ้างชื่อ
คอลัมน์เก่าไว้เพื่อลบออกจากฐานข้อมูลเก่าเท่านั้น)

# SCDC – ระบบจัดการงานรถ Handling (MVP v14 — แก้บั๊ก Pause หลายคนขับ + ตัดชั้นวางสูงสุด + งานที่รอรีวิว)

### Driver — แก้บั๊ก "หยุดชั่วคราว" ตอนมีหลายคนขับ
ปัญหาเดิม: กด "หยุดชั่วคราว" ได้เฉพาะคนขับ "หลัก" เท่านั้น ถ้าเป็นคนที่เข้าร่วมงานทีหลัง (ไม่ใช่คนแรก) จะกด
ไม่ได้เลย ตอนนี้แก้ให้คนขับที่ Active อยู่ในงานคนไหนก็กดได้ พร้อมพฤติกรรมตามที่ระบุ:
- **ปัญหาฝั่งผู้ขอ** (พื้นที่/ของยังไม่พร้อม) → หยุดทั้งงานเสมอ (สถานะงานหลักเป็น "หยุดชั่วคราว") เพราะกระทบ
  ทุกคนไม่ว่าจะมีกี่คัน
- **ปัญหาฝั่งรถ** → ถ้ายังมีคันอื่นทำงานอยู่ สถานะงานหลักจะ**ยังคงเป็น "กำลังดำเนินการ"** คนขับคนที่รายงาน
  ปัญหาจะถูกดึงออกจากงาน (เหมือนกด "ออกจากงาน") พร้อม**สร้างรายงานปัญหา/ขัดข้อง (Breakdown) ให้รถคันนั้น
  อัตโนมัติ** (สถานะรถเปลี่ยนเป็น "ขัดข้อง" ให้ Admin ไปกดแก้ไขทีหลัง) — ถ้าเป็นคนขับคนสุดท้ายที่เหลืออยู่ค่อย
  หยุดทั้งงานเหมือนเดิม
- ทดสอบครบ 3 กรณี: คนขับรองหยุดด้วยปัญหาฝั่งผู้ขอ (หยุดทั้งงาน), คนขับรองแจ้งปัญหารถขณะยังมีคนอื่นทำอยู่
  (งานเดินต่อ+สร้าง breakdown อัตโนมัติ), คนขับคนสุดท้ายแจ้งปัญหารถ (หยุดทั้งงาน)

### General — ตัด "ชั้นวางสูงสุด" ออกทั้งระบบ
เอาออกจากทุกจุด: schema ตาราง `tasks`/`vehicles`, ฟอร์มสร้าง/แก้ไขงาน, ฟอร์มสร้าง/แก้ไขรถ, การเช็คสิทธิ์รถ
ตอนมอบหมายงาน (`eligibility_issues`), หน้าแสดงรายละเอียดรถ, และคอลัมน์ในไฟล์ Excel ที่ export — **ไม่มีการ
กำหนดขีดจำกัดชั้นวางของรถแต่ละคันอีกต่อไป** (ยังเช็คความจุพาเลทตามปกติ ตัดออกเฉพาะเรื่องชั้นวางเท่านั้น)

⚠️ **ต้องลบ `backend/scdc.db` เก่าทิ้งก่อนรันรอบนี้** เพราะ schema เปลี่ยน (คอลัมน์ `max_rack_level` หายไป)

### User — เพิ่ม Section "งานที่รอรีวิว"
ในแท็บ "งานของฉัน" หลัง section "งานที่กำลังดำเนินการ" เพิ่ม section ใหม่แสดงงานที่ "เสร็จสิ้น" แล้วแต่ยัง
ไม่ได้ให้คะแนน พร้อมปุ่ม "ให้คะแนน" ตรงนั้นเลย ไม่ต้องไปหาในแท็บ "ประวัติ" อีกต่อไป

# SCDC – ระบบจัดการงานรถ Handling (MVP v11 — หน้า Driver สไตล์ Grab + ให้คะแนนละเอียดขึ้น)

## สิ่งที่เพิ่มล่าสุด (รอบนี้)

### User — ให้คะแนนละเอียดขึ้น
- ให้ดาว 1-5 ได้เหมือนเดิม แต่ตอนนี้ **ถ้าให้ต่ำกว่า 3 ดาว จะมีช่องคอมเมนต์โผล่ขึ้นมาให้กรอกเพิ่มเติม**
  (ไม่บังคับกรอก แต่ระบบเปิดโอกาสให้บอกว่าเกิดอะไรขึ้น) ถ้าให้ 3 ดาวขึ้นไปจะไม่โชว์ช่องนี้ ลดความยุ่งยาก

### Driver — รื้อหน้า "งานของฉัน" ใหม่ทั้งหมดให้คล้าย Grab
ตามภาพตัวอย่างที่ส่งมา ปรับโครงสร้างหน้าใหม่ทั้งหมด:
1. **พื้นที่หลัก (แทนตำแหน่งแผนที่)** — ถ้ามีงานที่กำลังทำอยู่ จะโชว์รายละเอียดงานนั้นแบบเต็มพร้อมปุ่มจัดการ
   ทันที ถ้าไม่มีงานอยู่เลย จะโชว์ "งานที่รับได้" ตามด้วย "งานที่คนอื่นกำลังทำ" แทน
2. **แถบสถานะ+รถ (แทนปุ่ม "ออนไลน์" ของ Grab)** — แสดงสถานะปัจจุบันกับรถที่เช็คอินอยู่ในแถวเดียวกัน
   - กดที่ **สถานะ** → เปิด sheet เปลี่ยนสถานะ (ว่าง/ไม่ว่าง/พัก/ขัดข้อง)
   - กดที่ **รถ** → เปิด sheet เช็คอิน/เช็คเอาท์
3. **การ์ด "งานของฉันวันนี้"** — สรุปจำนวนงานที่เสร็จ+พาเลทวันนี้ กดแล้วพาไปแท็บ "ประวัติ" ทันที
4. **แจ้งปัญหา/ขัดข้อง** ย้ายลงมาด้านล่างสุดตามที่ขอ (เลื่อนลงถึงจะเจอ)
5. **มุมขวาบนของ header** — เพิ่มไอคอนแชท 💬 เปิดเมนู "แชททั้งหมด" (แชททีมอยู่บนสุดเสมอ ตามด้วยแชทงานที่
   กำลังทำอยู่) และไอคอนกระดิ่งแจ้งเตือน 🔔 อยู่ขวาสุด
6. **มุมซ้ายบนของ header** — เปลี่ยนจาก "SCDC Dispatch" เป็นชื่อ-นามสกุล + รหัสพนักงานของคนขับเอง
   กดแล้วเปิดหน้าโปรไฟล์ทันที (แท็บ "โปรไฟล์" ที่เมนูล่างยังอยู่เหมือนเดิม เผื่ออยากเข้าทางนั้นด้วย)

**หมายเหตุ**: ยังไม่มีการ track "ชั่วโมงทำงาน" จริงจัง (ต้องมีระบบ clock-in/out แยกต่างหากซึ่งนอก scope
รอบนี้) การ์ด "งานของฉันวันนี้" เลยแสดงแค่จำนวนงานที่เสร็จ+พาเลทที่ทำได้ ไม่มีตัวเลขชั่วโมงทำงาน

## สถานะ Web Push (จากรอบก่อนหน้าที่ยังค้างไว้)

Backend/infrastructure สำหรับ Web Push (VAPID keys, subscribe/unsubscribe, hook เข้า `notify()`,
`manifest.json`, `service-worker.js`, `setup-https.bat`) **ทำและทดสอบผ่าน curl แล้ว** แต่ **ยังไม่เคย
รัน uvicorn ด้วย `--ssl-keyfile`/`--ssl-certfile` จริงจนจบ** และยังไม่เคยทดสอบกับเบราว์เซอร์จริงเลย —
ทุกส่วนถูกออกแบบให้ "เงียบ" ถ้ายังไม่ได้ตั้งค่า HTTPS (ปุ่มแจ้งเตือนในหน้าโปรไฟล์จะบอกว่าต้องมี HTTPS ก่อน
ไม่ error อะไร) เพราะงั้นใส่มาให้ในนี้ด้วยแต่ยังไม่นับว่าเป็นฟีเจอร์ที่ "เสร็จ" — สั่งให้ทำต่อได้เมื่อพร้อม

## สรุปงาน LAN Deployment (รอบนี้)

**ปัญหาเดิม**: รันด้วย `uvicorn main:app --reload` ซึ่ง default bind แค่ `127.0.0.1` (localhost) ทำให้เข้าได้
เฉพาะเครื่องที่รันเซิร์ฟเวอร์เอง คนอื่นในวง LAN เข้าไม่ได้เลย และไม่มีวิธีเริ่มระบบที่ไม่ต้องพิมพ์คำสั่งเอง

**สิ่งที่ตรวจสอบแล้วว่า "ไม่ต้องแก้"** (สถาปัตยกรรมถูกต้องอยู่แล้วตั้งแต่แรก):
- **Frontend ไม่มี hardcode `localhost`/`127.0.0.1` เลย** — ใช้ `const API = ""` แล้วเรียก `fetch(API + path)`
  ทุกจุด ซึ่งเป็น relative path อิงจาก origin ปัจจุบันอัตโนมัติ เปิดจาก IP ไหนก็เรียก API เครื่องนั้นเอง
- **Static file serving ถูกต้องอยู่แล้ว** — FastAPI serve หน้าเว็บที่ route `/` โดยตรง ไม่ต้องเปิดไฟล์
  `frontend/index.html` เอง
- **ไม่มี CORS middleware และไม่จำเป็นต้องมี** — Frontend กับ Backend serve จาก origin เดียวกันอยู่แล้ว
  (same-origin architecture) การเพิ่ม CORS โดยไม่จำเป็นจะยิ่งเสี่ยงด้านความปลอดภัยเปล่าๆ
- **SQLite ถูกต้องอยู่แล้ว** — client ทุกเครื่องคุยผ่าน HTTP ไป FastAPI เท่านั้น ไม่มีใครแตะไฟล์ `scdc.db`
  โดยตรง (schema/business logic ไม่ถูกแตะต้องเลยในรอบนี้ ตามที่กำชับไว้)

**สิ่งที่เพิ่มจริง**:
- `start-server.bat` — โหมด LAN/ทีม: เช็ค Python → สร้าง/ใช้ virtual environment → ติดตั้ง dependencies
  อัตโนมัติ → ตรวจ LAN IP ของเครื่อง → พยายามเปิด Windows Firewall (เฉพาะ private network เท่านั้น
  ถ้าไม่ใช่ Admin จะแจ้งเตือนแต่ยังรันต่อได้) → รัน `uvicorn main:app --host 0.0.0.0 --port 8000`
  (ไม่มี `--reload`) → แสดง URL ทั้งสองแบบให้เห็นชัดเจน
- `run-dev.bat` — โหมด dev เดิม (`--reload`, localhost อย่างเดียว) แยกออกมาให้ชัดเจนไม่ปนกับโหมดทีม

**⚠️ อัปเดต (แก้บั๊ก)**: เวอร์ชันแรกของ `.bat` ทั้งสองไฟล์ใช้โครงสร้าง `if (...) else (...)` ซ้อนกันเยอะ ซึ่งมีความเสี่ยง
ที่จะพังทันที (หน้าต่างดำแล้วดับไปเลยโดยไม่ทันเห็น error) ถ้าโฟลเดอร์ที่แตกไฟล์ zip ไปวางมีวงเล็บหรืออักขระ
พิเศษอยู่ในชื่อ (เช่น `scdc-mvp (1)` ที่เกิดจากดาวน์โหลดซ้ำ) เพราะวงเล็บในชื่อโฟลเดอร์ไปชนกับ syntax ของ
if/else — **แก้แล้วโดยเปลี่ยนไปใช้ `goto`/label แทนเกือบทั้งหมด** ซึ่งทนทานกว่ามากไม่ว่าโฟลเดอร์จะชื่ออะไร
ก็ตาม ถ้ายังเจอปัญหาอยู่ แนะนำให้เปิด Command Prompt ขึ้นมาก่อน แล้วพิมพ์ชื่อไฟล์รันแทนการดับเบิลคลิก
จะได้เห็นข้อความ error ค้างอยู่ในหน้าต่างแทนที่จะดับไปเฉยๆ

**ผลทดสอบจริง** (จำลองด้วยการยิง request ไปที่ IP เครือข่ายจริงของเครื่องแทน localhost):
| ทดสอบ | ผล |
|---|---|
| เข้าผ่าน `http://localhost:8000` | ✅ 200 |
| เข้าผ่าน `http://127.0.0.1:8000` | ✅ 200 |
| เข้าผ่าน IP เครือข่ายจริงของเครื่อง (จำลอง "เครื่องอื่นในวง LAN") | ✅ 200 |
| Login ผ่าน IP เครือข่าย | ✅ ได้ token ปกติ |
| ดู/สร้าง Task, ดู Driver, ดู Vehicle ผ่าน IP เครือข่าย | ✅ ทำงานปกติทุกจุด |
| หน้าเว็บ (frontend) โหลดผ่าน IP เครือข่าย | ✅ โหลดถูกต้อง |
| Server bind เป็น 0.0.0.0 (ฟังทุก interface) | ✅ ยืนยันแล้วด้วย log ของ uvicorn |

**ข้อจำกัดที่ควรรู้**:
- ทดสอบจริงได้แค่ "เครื่องเดียวกันเรียกผ่าน IP เครือข่ายของตัวเอง" เพราะ sandbox นี้ไม่มีเครื่องที่สองแยก
  ต่างหากให้ทดสอบจริง — ยังไม่ได้ทดสอบจากมือถือ/โน้ตบุ๊กเครื่องจริงอีกเครื่องบนเครือข่าย Wi-Fi จริง
  แต่เงื่อนไขทางเทคนิคที่จำเป็น (bind 0.0.0.0, ไม่มี hardcode localhost, ไม่ติด CORS) ตรวจสอบและยืนยันครบแล้ว
- Windows Firewall: `start-server.bat` พยายามเปิด rule ให้อัตโนมัติ แต่ถ้าไม่ได้รันแบบ Administrator
  จะสร้าง rule ไม่ได้ (จะแจ้งเตือนในหน้าจอ) ผู้ใช้ต้องคลิกขวา "Run as administrator" เอง หรือเปิด port
  8000 เองใน Windows Firewall
- SQLite รองรับผู้ใช้พร้อมกันได้ในระดับทีมเล็กๆ (การเขียนถูก serialize อัตโนมัติ) เหมาะกับใช้งานภายใน
  ทีม/แผนก ไม่ใช่ระดับองค์กรใหญ่ที่มีคนใช้พร้อมกันเยอะมากๆ — ถ้าต้องขยายควรย้ายไป Postgres ตามที่เคย
  ระบุไว้ใน README ส่วนเดิม
- ยังไม่มี HTTPS — เหมาะกับใช้ในวง LAN ภายในที่ไว้ใจได้ ไม่ควรเปิดออกอินเทอร์เน็ตสาธารณะตรงๆ

# SCDC – ระบบจัดการงานรถ Handling (MVP v6 — ผัง Location ใหม่ทั้งระบบ)

## สิ่งที่เพิ่มล่าสุด (รอบนี้ — "รอบ Location")

เปลี่ยนระบบ Location ทั้งหมดจากการพิมพ์ข้อความอิสระ เป็นระบบ **โซน + Pattern validation**
ตามผังโกดังจริง:

| โซน | รูปแบบ | เลือกได้กี่จุด | ตัวอย่าง |
|---|---|---|---|
| ลานปูน | ประตู 1-7 | จุดเดียว | `ลานปูน-3` |
| ประตู | In 1-58 / Out 59-85 | จุดเดียว | `ประตู-12` (In), `ประตู-67` (Out) |
| ลาน Sort | จุดเดียวตายตัว | จุดเดียว | `ลาน Sort` |
| Mezzanine | ชั้น 1-4 × ฝั่งซ้าย(Cross dock)/ขวา(Double Deep) | จุดเดียว | `Mezzanine-2-ซ้าย (Cross dock)` |
| Selective Rack | BAA01–BBH39 + level(A-G)+slot(1-2) ไม่บังคับ | **หลายจุดได้** | `BAA01A1` |
| Double Deep | AAA01–AAF74 + level+slot ไม่บังคับ | **หลายจุดได้** | `AAA01G1` |

- **ฟอร์มสร้าง/แก้ไขงาน** เปลี่ยนเป็นเลือกโซนก่อน แล้ว UI ปรับเปลี่ยนตามโซนที่เลือกอัตโนมัติ
  (dropdown/สองขั้นตอน/พิมพ์แล้วกดเพิ่มเป็น chip) พร้อม validate pattern ทันทีก่อน submit
- ค่าที่บันทึกยังเป็น **string เดียว** เสมอ (จุดที่เลือกหลายจุดจะคั่นด้วยจุลjúa comma เช่น `BAA01A1,BAA02A1`)
- **Admin ไม่ต้องสร้างรหัสตำแหน่งทีละรายการอีกต่อไป** — จัดการแค่ "โซน" (ชื่อ + pattern) ที่ Settings →
  โซน และเพิ่มโซนใหม่ได้เองในอนาคตถ้าต้องการ (โซนใหม่ที่ไม่ใช่ 6 โซนหลักจะได้ UI แบบพิมพ์ตรวจ pattern
  อัตโนมัติ ไม่ต้องเขียนโค้ดเพิ่ม)
- **เมทริกซ์รถ-โซน** (Settings → เมทริกซ์รถ-โซน): ตาราง checkbox กำหนดว่าประเภทรถไหนทำงานโซนไหนได้บ้าง
  ตอน Assign/Reassign/รับงานเอง ระบบจะเช็คเงื่อนไขนี้ด้วย (override ได้เหมือนเงื่อนไขอื่นๆ)
- กฎประเภทงาน (Task Rules) เปลี่ยนจากพิมพ์ชื่อโซนเองเป็นเลือกจาก dropdown ป้องกันพิมพ์ผิด

### หมายเหตุด้าน data model

- ตาราง `locations` เดิมถูกแทนที่ด้วย `zones` (pattern-based) + `vehicle_type_zones` (matrix)
- ตาราง `tasks` เพิ่มคอลัมน์ `from_zone`/`to_zone` เก็บคู่กับ `from_location`/`to_location` (string ที่
  ผู้ใช้เห็น) เพื่อให้ backend เช็คสิทธิ์รถและคำนวณประเภทงานได้แม่นโดยไม่ต้อง parse string ทุกครั้ง
- ฐานข้อมูลเป็นไฟล์ใหม่ทั้งหมด (`scdc.db` เดิมใช้ต่อไม่ได้ ต้องลบแล้วให้ระบบสร้างใหม่)

## ยังไม่ได้ทำ (รอ requirement รอบถัดไป)

- General#1 (แจ้งเตือนตอนปิดแอป) — พักไว้ก่อน
- General#2/#3 (หลายคนต่อ 1 งาน + แสดงชื่อ+จำนวน)
- Admin#6 (ห้องแชทกลาง Admin↔Driver + @mention)
- Admin#8 (Promote พนักงานเป็น Driver + License ต่อประเภทรถ)

# SCDC – ระบบจัดการงานรถ Handling (MVP v4)

## สิ่งที่เพิ่มล่าสุด (รอบนี้)

### General
- **รองรับหน้าจอคอมพิวเตอร์แล้ว** — บนจอกว้าง (≥900px) เมนูจะย้ายมาเป็น sidebar ด้านซ้าย, เนื้อหาขยายให้ใช้พื้นที่ได้เต็มขึ้น, และ popup ต่าง ๆ จะกลายเป็น dialog กลางจอแทนการเลื่อนขึ้นจากขอบล่าง หน้าจอมือถือยังทำงานเหมือนเดิมทุกอย่าง (ไม่มี breaking change)

### Driver
- **บังคับเช็คอินรถทันทีหลังล็อกอิน** — ถ้ายังไม่ได้ขึ้นรถ ระบบจะพาไปหน้าเช็คอินก่อนเข้าใช้งานอื่น และแสดง**เฉพาะรถที่ยังไม่มีคนขับคนอื่นเช็คอินอยู่**ให้เลือก (ถ้ากำลังทำงานค้างอยู่ระบบจะไม่บังคับเช็คอินซ้ำ)
- **แถบด้านบนแสดงสถานะของตัวเอง** พร้อม badge งานปัจจุบัน (ถ้ามี) กดแล้วเปิดดูรายละเอียด/ทำ action ได้ทันทีโดยไม่ต้องสลับแท็บ
- **รับช่วงงานที่คนอื่นกำลังทำได้** — แท็บ "งานที่ว่าง" มีส่วน "งานที่คนอื่นกำลังทำ" กดรับช่วงต่อได้เลย (ระบบยังตรวจสิทธิ์ขับ/ความจุ/สถานะว่างเหมือนเดิม)

### Admin
- **แก้ไขความจุ (Cap) ของรถแต่ละคันได้** — แท็บ Ops → รถ → ปุ่ม "แก้ไข" ต่อคัน ปรับความจุพาเลท/ชั้นวางสูงสุด/ประเภทรถได้
- **เลือกคนขับที่ Online ได้แม้ไม่ว่าง** — ตอน Assign/Reassign มีรายชื่อคนขับทั้งหมดพร้อม badge สถานะให้เลือกโดยตรง ไม่ต้องพิมพ์รหัสพนักงานเอง (เลือกคนที่ไม่ว่างได้ ระบบจะเตือน eligibility ให้กด override ยืนยันอีกที)

### User
- **กดการแจ้งเตือนแล้วพาไปที่ถูกจุด** — ถ้าเป็นแจ้งเตือนเกี่ยวกับงาน จะเปิดหน้ารายละเอียดงาน ถ้าเป็นข้อความแชท จะเปิดหน้าแชทของงานนั้นเลย

# SCDC – ระบบจัดการงานรถ Handling (MVP v3)

เวอร์ชันรันได้จริง ครบเกือบทุกฟีเจอร์ตามสเปก ใช้ FastAPI ตัวเดียว serve ทั้ง API และหน้าเว็บ
(SQLite ไม่ต้องติดตั้งฐานข้อมูลแยก) **หน้าแอปเป็นภาษาไทยทั้งหมด**

## วิธีรัน

ต้องมี Python 3.10 ขึ้นไป

```bash
cd backend
pip install -r requirements.txt
python -m uvicorn main:app --reload
```

เปิด **http://localhost:8000** ระบบจะสร้างไฟล์ `backend/scdc.db` และ seed ข้อมูลให้อัตโนมัติ
ครั้งแรกที่รัน ลบไฟล์นี้เพื่อล้างข้อมูลทั้งหมด (และลบไฟล์ใน `backend/uploads/` ถ้าต้องการล้างรูปที่อัปโหลดด้วย)

## บัญชีทดสอบ

| บทบาท   | รหัสพนักงาน | รหัสผ่าน     | หมายเหตุ |
|--------|-------------|--------------|-------|
| Admin  | admin001    | admin123     | |
| User   | user001     | user123      | |
| Driver | driver001   | driver123    | สิทธิ์ขับ: RT, PE |
| Driver | driver002   | driver123    | สิทธิ์ขับ: RT, FORKLIFT |
| Driver | driver003   | *(รหัสอะไรก็ได้)* | ทดสอบ flow ตั้งรหัสผ่านครั้งแรก — ล็อกอินด้วยรหัสอะไรก็ได้เพื่อเจอหน้าตั้งรหัสผ่านใหม่ |

รถที่ seed ไว้: `RT-001`, `RT-002` (RT), `PE-001` (PE), `FORK-001` (FORKLIFT)
จุดพื้นที่ที่ seed ไว้: **โซนใหม่ทั้งหมด** — ดูตารางโซนที่ด้านบนสุดของไฟล์นี้ (ลานปูน/ประตู/ลาน Sort/Mezzanine/Selective Rack/Double Deep) ตัวอย่าง `FLOOR-A1`/`RACK-B2` แบบเดิมใช้ไม่ได้แล้ว

**ข้อควรทราบ**: ทุกครั้งที่ Driver ล็อกอินใหม่ ระบบจะรีเซ็ตสถานะเป็น "ยังไม่ขึ้นรถ" (ตามที่ระบุใน
requirement) ต้องเช็คอินรถ + แบตเตอรี่ก่อนถึงจะรับงานได้ — ยกเว้นถ้ากำลังมีงาน In Progress อยู่
(สถานะ Busy) ระบบจะไม่รีเซ็ตทับเพื่อไม่ให้งานที่ทำค้างอยู่หลุด

## สิ่งที่ทำเพิ่มในรอบนี้ (ตามที่ขอ)

### General
1. **แปลหน้าแอปเป็นภาษาไทยทั้งหมด** (ปุ่ม, label, สถานะ, ข้อความแจ้งเตือน)
2. **Register เพิ่มชื่อ-นามสกุล** และ validate เบอร์โทร (ต้องเป็นรูปแบบเบอร์ไทย 9-10 หลัก ขึ้นต้นด้วย 0)
   + validate cost center (ต้องเป็นตัวเลข 5 หลัก) ทั้งตอนสมัครและตอนแก้โปรไฟล์
3. **แก้บั๊กข้อมูลถูก blank ระหว่างพิมพ์** — ต้นเหตุคือระบบ poll รีเฟรชหน้าทุก 3 วินาที แล้วฟอร์มที่อยู่ในแท็บ
   (เช่น เปลี่ยนรหัสผ่าน, เช็คอินรถ, สร้างบัญชีคนขับ) ถูกล้างค่าทิ้งไปด้วย ตอนนี้ระบบจะ**ข้ามการ re-render
   หน้าจอถ้า element ที่โฟกัสอยู่เป็น input/textarea/select ในแท็บนั้น** พิมพ์เสร็จ/คลิกออกจากช่องแล้วค่อยรีเฟรช
4. **ระบบแชทเฉพาะงาน** — แชทได้เฉพาะ: User ที่เปิดงานนั้น, Driver คนใดก็ตามที่เคยรับงานนี้ (แม้จะถูก
   reassign ออกไปแล้วก็ยังเห็นประวัติแชทได้), และ Admin ทุกคน คนนอกกลุ่มนี้เรียก API จะได้ 403 ทันที

### User
1. **ไม่ต้องกรอก Pallet ID** ตอนสร้างงานแล้ว (เอาช่องออกจากฟอร์ม สร้าง/แก้ไข)
2. **Booking ต้องระบุวันเวลา** — เลือก "จองล่วงหน้า" แล้วจะมีช่อง datetime ให้กรอก (บังคับ ทั้ง frontend
   และ backend validate)
3. **Profile แก้ไขได้ทุกอย่างยกเว้นรหัสพนักงานกับ Role** — ชื่อ, เบอร์ติดต่อ, Cost Center (เฉพาะ User)

### Driver
1. **รับงานเองได้จากหน้า "งานที่ว่าง"** โดยไม่ต้องรอ Admin กด Assign — ใช้รถที่เช็คอินไว้อัตโนมัติ
   (ระบบยังตรวจสิทธิ์ขับ/ความจุ/ชั้นวางให้เหมือนที่ Admin assign ให้)
2. **หน้า "งานที่ว่าง" แสดงชื่อผู้ขอ + เบอร์ติดต่อ** ของแต่ละงาน
3. **ล็อกอินแล้ว = ยังไม่ขึ้นรถ** ต้องเช็คอินรถ+ระบุ % แบตก่อนถึงจะเป็น "ว่าง" (Available)
4. **งานที่ถูก Assign จะขึ้นในหน้า "งานที่ว่าง" ทันที** (ส่วนบนสุด แยกเป็น "งานปัจจุบันของฉัน")
5. **ตอน Accept งานต้องระบุ % แบตปัจจุบัน** เสมอ (ใช้ sheet เดียวกับตอนรับงานเอง)
6. **Pause ต้องเลือกหมวดปัญหา** — "ฝั่งผู้ขอ (พื้นที่/ของ)" หรือ "ฝั่งรถ" พร้อมปุ่มสาเหตุสำเร็จรูป (เช่น
   "ประตูยังไม่ถูกเปิด", "แบตเตอรี่ต่ำ") เลือกแล้วแก้ไขข้อความเพิ่มเติมได้
7. **หน้าประวัติมี Dashboard สรุปผลงาน** เลือกดูรายวัน/รายเดือนได้ พร้อมจำนวนงานที่เสร็จ + พาเลทรวม

### Admin
1. **Dashboard ใช้งานได้จริง** — เพิ่ม KPI (คนขับว่าง, รถว่าง, งานค้างนาน) และดึงบอร์ดจ่ายงาน
   (มอบหมาย/มอบหมายใหม่ได้ทันที) มาไว้ในแท็บ Dashboard เลย ไม่ต้องสลับไปแท็บ Dispatch
2. **แทนที่ Recent Task ด้วย Dispatch board** ตัวเดียวกับแท็บ "จ่ายงาน" (ฟังก์ชัน `renderDispatchBoard`
   ใช้ร่วมกันทั้งสองแท็บ)

## ฟีเจอร์เดิมที่ยังอยู่ครบ (จากรอบก่อนหน้า)

State machine ครบ (`Waiting → Assigned → In Progress → Completed` + `Cancelled`/`Pause`),
RBAC บังคับที่ backend, ประวัติการมอบหมายงาน (`task_assignments`) ไม่เขียนทับของเดิม, ตรวจสอบ
eligibility ตอน assign/reassign พร้อม override ได้, แก้ไขงาน/เปลี่ยนความสำคัญ, เช็คอินรถ, แจ้ง/แก้ไข
Breakdown, เปลี่ยนรหัสผ่าน, สร้างบัญชี Driver แบบตั้งรหัสทีหลัง, ส่งประกาศ, แจ้งเตือนงานค้างนาน,
ETA, อัปโหลดรูปงาน, ตาราง Locations/Task Rules/Audit Log ที่ Admin แก้ไขได้จริง

## ยังไม่ได้ทำ (ตั้งใจตัดออก บอกไว้ตรงนี้ชัดเจน)

- Web Push / PWA ติดตั้งเป็นแอปได้ / Service Worker
- PostgreSQL (ใช้ SQLite เพื่อให้รันง่าย schema ใกล้เคียงพอย้ายได้)
- WebSocket จริง (ใช้ polling ทุก 3 วิ ทั้งหน้าจอทั่วไปและแชท)
- Email / Microsoft Teams
- ระบบ License หมดอายุ (ยังไม่มี data model)
- Dispatch scoring แบบให้คะแนนละเอียด (ตอนนี้เป็นแค่ filter คุณสมบัติที่ผ่าน/ไม่ผ่าน)

## ลองใช้งานตาม flow เต็ม

1. **user001** → โปรไฟล์ → แก้ชื่อ/เบอร์ → บันทึก (เช็คว่าไม่ล้างค่าระหว่างพิมพ์)
2. **user001** → สร้างงานแบบ "จองล่วงหน้า" → ลองไม่ใส่วันเวลาดู (ต้อง error) → ใส่แล้วส่ง
3. **driver001** → เช็คอินรถ RT-001 + แบต 90% → สถานะเปลี่ยนเป็น "ว่าง"
4. **driver001** → แท็บ "งานที่ว่าง" → เห็นชื่อ/เบอร์ผู้ขอ → กด "รับงานนี้" → ใส่ % แบต → ยืนยัน
   (งานข้าม Waiting→Assigned พร้อม accept ในตาเดียว)
5. **driver001** → เริ่มงาน → ระหว่างทำงาน กด "หยุดชั่วคราว" → เลือกฝั่งรถ → "แบตเตอรี่ต่ำ" → ยืนยัน
6. **driver001** → กด "แชท" บนการ์ดงาน → พิมพ์คุยกับ user001
7. **user001** → เปิดแชทงานเดียวกัน → เห็นข้อความ → ตอบกลับ
8. **driver002** (ไม่เคยรับงานนี้) → เรียก `GET /tasks/{id}/messages` ตรง ๆ → ต้องได้ 403
9. **admin001** → แท็บ Dashboard → เห็น KPI + บอร์ดจ่ายงานในหน้าเดียว → ลอง "มอบหมายใหม่" งานที่ driver001
   กำลังทำอยู่ (จะเห็น eligibility ผ่านหรือไม่ผ่าน ถ้าไม่ผ่านมีปุ่ม override)
10. **driver001** → ทำงานต่อ → เสร็จงาน → ไปแท็บ "ประวัติ" → เลือกรายวัน/รายเดือน → เห็นจำนวนงาน+พาเลทรวม

## API ที่เพิ่ม/แก้ไขใหม่ในรอบนี้

```
PUT  /me                         แก้ไขชื่อ/เบอร์/cost center ของตัวเอง (ยกเว้น employee_id, role)
POST /tasks/{id}/self-assign     (DRIVER) รับงานเอง ใช้รถที่เช็คอินไว้ ต้องส่ง battery_level
POST /tasks/{id}/accept          (DRIVER) ตอนนี้ต้องส่ง battery_level ด้วย
POST /tasks/{id}/pause           (DRIVER) ตอนนี้ต้องส่ง {category: 'user'|'vehicle', reason}
GET  /drivers/me/stats           (DRIVER) ?period=day|month&date=... -> {task_count, pallet_total}
GET  /tasks/{id}/messages        แชทเฉพาะผู้เกี่ยวข้องกับงาน
POST /tasks/{id}/messages        ส่งข้อความในแชทงาน
```

`POST /tasks` และ `PUT /tasks/{id}` รับ `scheduled_at` เพิ่ม (บังคับเมื่อ `request_type="Booking"`)
และไม่ต้องส่ง `barcode_pallet_id` แล้ว (field ยังอยู่ใน DB เผื่ออนาคต แต่ frontend ไม่ขอกรอกแล้ว)

ดู endpoint อื่น ๆ ทั้งหมดในซอร์สโค้ด `backend/main.py` — คอมเมนต์และชื่อฟังก์ชันเป็นภาษาอังกฤษเพื่อให้
dev อ่านง่าย ส่วนข้อความที่ผู้ใช้เห็นจริงทั้งหมดอยู่ใน `frontend/index.html` เป็นภาษาไทย
